DIAGNOSTYKA PO AKTUALIZACJI

Home Assistant nie działa po aktualizacji: co sprawdzić i jak odzyskać system?

Autor: Tomasz Furdal · HA Expert

Aktualizacja Home Assistant zwykle przebiega bez problemu. Czasem jednak po restarcie nie otwiera się panel, część integracji jest niedostępna, automatyzacje nie reagują albo system zaczyna się ponownie uruchamiać.

Nie każda awaria zauważona po aktualizacji oznacza uszkodzenie całej instalacji. Najbezpieczniej najpierw określić zakres problemu, zebrać informacje i dopiero wtedy wybrać sposób naprawy.

KROK 1

Najpierw ustal, co dokładnie nie działa

  • Panel w ogóle się nie otwiera: problem może dotyczyć Home Assistant, hosta, maszyny wirtualnej, kontenera, sieci albo adresu używanego do połączenia.
  • Panel działa, ale integracje lub encje są niedostępne: zwykle nie jest to awaria całej centrali. Warto zacząć od konkretnej integracji i jej komunikatów.
  • Automatyzacje nie działają: sprawdź, czy są włączone, czy ich wyzwalacze i warunki otrzymują dane oraz co pokazuje ślad wykonania.
  • Pojawiają się błędy albo restarty: zanotuj ich czas i częstotliwość. Powtarzalny wzorzec pomaga odróżnić problem Core od hosta lub pamięci masowej.
  • Nie działa tylko jeden dodatek lub komponent niestandardowy: diagnozuj ten element oddzielnie, zamiast od razu cofać cały system.

Jeśli problemem jest pojedynczy stan unavailable, zobacz również poradnik o niedostępnej encji w Home Assistant.

KROK 2

Sprawdź, co naprawdę zostało zaktualizowane

Zbieżność w czasie nie zawsze oznacza związek przyczynowy. W tym samym momencie mógł zmienić się adres IP urządzenia, wygasnąć token usługi chmurowej, zatrzymać dysk albo pojawić się problem z routerem.

Ustal, czy aktualizacja dotyczyła Home Assistant Core, Home Assistant OS, Supervisor, dodatku, integracji producenta czy komponentu HACS. Zapisz wersję przed zmianą i po niej, przybliżoną godzinę oraz pierwszy widoczny objaw. Sprawdź też informacje o wydaniu i sekcję zmian niezgodnych wstecz dla aktualizowanego elementu.

Jeśli kilka rzeczy zaktualizowano jednocześnie, nie zakładaj od razu, która zawiniła. Najpierw porównaj czas aktualizacji z logami i pierwszym błędem.

BEZPIECZNE KONTROLE

Zacznij od zasilania, sieci, stanu hosta i logów

  • Sprawdź, czy host działa, ma zasilanie i jest widoczny w routerze albo konsoli maszyny wirtualnej.
  • Spróbuj lokalnego adresu IP lub poprawnej nazwy hosta. Niedziałający dostęp zdalny nie dowodzi, że Home Assistant zatrzymał się lokalnie.
  • Jeśli interfejs jest dostępny, przejrzyj Ustawienia → System → Logi oraz Naprawy. Najważniejszy jest pierwszy błąd po uruchomieniu, nie dziesiątki późniejszych skutków.
  • Sprawdź informacje systemowe i wolne miejsce. Pełny dysk może blokować zapis bazy, aktualizację i prawidłowy start usług.
  • W Home Assistant OS konsola i CLI pozwalają sprawdzić stan oraz logi Core, Supervisor i hosta. W Dockerze lub maszynie wirtualnej te same warstwy trzeba ocenić narzędziami platformy.

Nie restartuj wielokrotnie bez zapisania komunikatów. Restart może usunąć najłatwiejszy do uchwycenia moment wystąpienia błędu.

TRYB AWARYJNY

Recovery mode i Safe mode pomagają zawęzić źródło

Recovery mode pojawia się, gdy Home Assistant wykryje problem z konfiguracją i uruchomi minimalny zestaw integracji, aby umożliwić naprawę. Taki komunikat kieruje uwagę na konfigurację i błędy ładowania.

Safe mode uruchamia Home Assistant Core bez integracji niestandardowych, kart niestandardowych i motywów. Jeśli problem znika w tym trybie, źródła należy szukać poza samym Core, często w HACS lub innym elemencie niestandardowym.

Tryb bezpieczny jest narzędziem diagnostycznym, a nie naprawą. Przed wyłączaniem lub usuwaniem komponentów zapisz logi i ustal, który element faktycznie powoduje problem.

CZĘŚCIOWA AWARIA

Gdy Home Assistant działa, sprawdzaj warstwy osobno

  • Integracje: sprawdź status konfiguracji, ponowną autoryzację, komunikaty Napraw i logi konkretnej integracji.
  • Encje: porównaj, czy niedostępna jest jedna encja, całe urządzenie czy wszystkie urządzenia tej samej integracji.
  • Automatyzacje: sprawdź ślady, wyzwalacze, warunki i zależne encje. Aktualizacja mogła ujawnić stary błąd lub zmienione zachowanie usługi.
  • Dodatki: oddziel stan dodatku od stanu Home Assistant Core i sprawdź jego własny log.
  • HACS i komponenty niestandardowe: sprawdź zgodność oraz zgłoszenia autora. Nie aktualizuj kilku komponentów naraz podczas diagnozy.

Jedna niedziałająca integracja nie oznacza konieczności przywracania całej instalacji. Pomocne może być porównanie z poradnikami o integracjach i automatyzacjach Home Assistant.

HOST I INSTALACJA

Problem może leżeć poniżej Home Assistant

Jeżeli panel nie odpowiada, Core nie startuje albo host ciągle się uruchamia ponownie, sprawdź warstwę instalacji. W Home Assistant OS będzie to stan systemu i pamięci masowej, w Dockerze także kontener, wolumeny i logi silnika, a w maszynie wirtualnej zasoby, dysk i konsola hypervisora.

Nagły brak wielu integracji jednocześnie może wynikać z problemu sieci, DNS, USB lub nośnika danych. Przy instalacji na PC lub mini PC warto znać sposób uruchomienia systemu i miejsce przechowywania danych; szerzej opisuje to poradnik o Home Assistant na PC, mini PC i laptopie.

Jeśli pojawiają się błędy wejścia-wyjścia, uszkodzenie systemu plików albo niestabilność sprzętu, dalsze restarty i aktualizacje mogą pogorszyć sytuację. Najpierw zabezpiecz dostępne dane.

BACKUP I COFNIĘCIE

Kopia zapasowa jest planem odzyskania, nie pierwszym odruchem

Aktualny backup pozwala odzyskać konfigurację i wybrane dane, ale przywrócenie nadpisuje wybrane części bieżącego systemu. Może więc cofnąć automatyzacje, urządzenia, historię lub inne zmiany wykonane po utworzeniu kopii.

Przed przywróceniem sprawdź datę, zakres, miejsce przechowywania i dostęp do klucza szyfrowania. Jeśli system nadal częściowo działa, zabezpiecz aktualne logi i konfigurację. Dopiero potem zdecyduj, czy lepsze jest przywrócenie całego backupu, tylko wybranej części czy naprawa konkretnego elementu.

Szczegóły przygotowania i odtwarzania opisuje poradnik backup Home Assistant: kopia zapasowa i przywracanie.

NIE RÓB TEGO W PANICE

Przypadkowe zmiany utrudniają odzyskanie systemu

  • Nie kasuj losowo plików konfiguracji, bazy danych ani katalogów komponentów.
  • Nie usuwaj i nie dodawaj ponownie wielu integracji naraz.
  • Nie instaluj kolejnych aktualizacji tylko po to, aby sprawdzić, czy problem zniknie.
  • Nie przywracaj starego backupu bez sprawdzenia, co zostanie nadpisane.
  • Nie resetuj całej instalacji, dopóki nie wiadomo, czy problem dotyczy Core, hosta, sieci czy jednego dodatku.
  • Nie udostępniaj publicznie pełnych logów bez sprawdzenia, czy nie zawierają adresów, tokenów lub innych danych prywatnych.

Dobra diagnostyka zmienia jedną rzecz naraz i po każdym kroku sprawdza wynik. Dzięki temu wiadomo, co rzeczywiście pomogło.

KIEDY PRZERWAĆ

Dokładniejsza diagnostyka jest potrzebna, gdy ryzyko rośnie

  • Home Assistant nie startuje albo wpada w pętlę restartów.
  • W logach są błędy migracji, bazy danych, systemu plików lub odczytu i zapisu.
  • System uruchamia się tylko w Recovery mode lub Safe mode, ale źródło nadal nie jest jasne.
  • Wiele niezależnych integracji przestało działać jednocześnie.
  • Problem może dotyczyć Dockera, maszyny wirtualnej, Home Assistant OS, dysku albo sprzętu.
  • Nie masz pewności, czy backup jest kompletny i jakie dane zostaną cofnięte.

W takiej sytuacji kolejne próby na chybił trafił mogą utrudnić odzyskanie konfiguracji. Warto zatrzymać zmiany, zachować logi oraz spisać wersje i wykonane kroki.
