LOKAL DRIFT

Hvad virker reelt i Home Assistant uden internet?

Forfatter: Tomasz Furdal · HA Expert

Home Assistant kører på hardware i hjemmet og kan styre lokale enheder uden internetforbindelse. Det betyder ikke, at alle dele af et smart home bevarer fuld funktion.

Et reelt system kombinerer normalt lokale enheder, cloud-tjenester og netværksinfrastruktur. Et bedre spørgsmål end “virker Home Assistant uden internet?” er derfor “hvad afhænger hver funktion i mit hjem af?”.

TRE FEJL

Internetfejl, routerfejl og Home Assistant-fejl er forskellige hændelser

  • Internet- eller WAN-fejl: forbindelsen til udbyderen er nede, mens router, LAN, Wi-Fi og Home Assistant kan fortsætte.
  • Fejl i router eller lokalnet: enheder kan miste Wi-Fi, IP-adresser eller forbindelsen til Home Assistant, selv om serveren kører.
  • Fejl på Home Assistant-værten: enhedernes netværk kan stadig eksistere, men automatiseringer udført af Home Assistant kører ikke.

Fejlene har forskellige konsekvenser. Sætningen “internettet er nede” placerer ofte for mange problemer på WAN-forbindelsen.

LAN OG DHCP

Routeren kan holde hjemmenetværket i drift uden WAN

En router forbinder normalt enheder på LAN, leverer Wi-Fi og tildeler adresser via DHCP. Når kun internettet forsvinder, kan funktionerne fortsætte. Home Assistant, en telefon og en lokal Wi-Fi-enhed kan blive på samme netværk og kommunikere.

En routerfejl er mere alvorlig. Wi-Fi kan forsvinde, og kablede eller trådløse enheder kan miste forbindelsen til hinanden. Virkningen afhænger af separate access points, switches og af, om en bestemt funktion behøver routeren.

DHCP-reservationer eller en anden forudsigelig adressering hjælper stabil kommunikation og fejlfinding på vigtige enheder. De beskytter ikke mod fejl i selve routeren eller strømsvigt i netværksudstyret.

INTEGRATIONSTYPE

Local og Cloud beskriver vejen, Polling og Push opdateringsmetoden

  • Local Polling: Home Assistant spørger enheden direkte på lokalnettet om dens aktuelle status.
  • Local Push: en lokal enhed eller hub sender en statusændring direkte til Home Assistant.
  • Cloud Polling: Home Assistant spørger regelmæssigt en producenttjeneste via internettet.
  • Cloud Push: en ændring når Home Assistant gennem producentens cloud-tjeneste.

Polling betyder ikke cloud, og Push betyder ikke lokal drift. Robusthed afhænger især af, om kommunikationsvejen er lokal, og om alle dele på vejen er tilgængelige.

DET DER VIRKER

Lokale enheder og automatiseringer kan fortsætte normalt

Når Home Assistant og den lokale infrastruktur kører, kan lokalt koordinerede Zigbee-enheder, lokale Wi-Fi-enheder og lokale sensorer virke uden internet. Det kan omfatte lys, gardiner, varme, scener og gruppestyring.

En lokal automatisering kan modtage bevægelse fra en Zigbee-sensor og tænde et lokalt styret lys. Den behøver ikke WAN, hvis ingen udløsere, betingelser eller mål anvender en utilgængelig cloud-tjeneste.

Betegnelsen “Wi-Fi” beviser ikke lokal styring. En enhed kan være forbundet til hjemmets trådløse netværk og alligevel kun modtage kommandoer gennem producentens server.

DET DER STOPPER

Cloud, fjernadgang og eksterne data kræver internet

Cloud Polling- og Cloud Push-integrationer, enheder der kun bruger cloud, vejrudsigter, energipriser og andre eksterne data kan blive utilgængelige. Fjernadgang via internet stopper også, selv om panelet stadig kan åbnes lokalt.

Nogle stemmetjenester kræver cloud. En lokal stemmepipeline kan fungere uden den, når alle komponenter kører i hjemmet. Den konkrete opsætning er vigtigere end assistentens navn.

En automatisering kan være gemt og udført lokalt, men stadig fejle, hvis dens betingelse bruger en cloud-entitet, eller målet kun findes via internet. Planlæg håndtering af utilgængelige tilstande i stedet for at betragte den seneste værdi som aktuel.

SCENARIE 1

Internettet er nede, men router og Home Assistant kører

En telefon på hjemmets Wi-Fi kan stadig åbne det lokale Home Assistant-panel. En Zigbee-bevægelsessensor registrerer bevægelse, automatiseringen kører på serveren, og et lokalt styret lys tænder som normalt.

Samtidig kan en cloud-baseret stikkontakt være utilgængelig, vejrudsigten opdateres ikke, og adgang udefra stopper. Én fejl giver derfor forskellige resultater i samme system.

SCENARIE 2

Routeren er stoppet

Zigbee er et separat radionetværk og kan fortsat eksistere. Hvis koordinatoren er tilsluttet direkte til den aktive Home Assistant-vært, kan ZHA-kommunikation med Zigbee-enheder forblive tilgængelig. En netværkskoordinator, Zigbee2MQTT på en anden computer eller andre LAN-forbundne dele kan miste forbindelsen til Home Assistant.

Wi-Fi-enheder mister normalt forbindelsen, når routeren også fungerer som access point. Med separate access points og switches kan en del af LAN fortsætte, men resultatet afhænger af topologi, DHCP, adressering og kommunikationsmetode. Der findes ingen enkelt regel for alle hjem.

SCENARIE 3

Home Assistant er stoppet

Enheder kan blive i deres netværk, men logik udført af Home Assistant er utilgængelig. En sensor kan fortsat sende en hændelse i Zigbee-netværket, mens en Home Assistant-automatisering ikke reagerer.

En fysisk betjening på lys, termostat eller gardin kan fortsat virke, hvis den styrer enheden uafhængigt. Direkte Zigbee-binding mellem kompatibel betjening og lys kan også omgå Home Assistant. Adfærden afhænger af systemdesign og enhedsfunktioner, så vigtig betjening bør ikke kun afhænge af én central.

KONTROL

Hvordan vurderer du robustheden i dit eget smart home?

  • Kontrollér integrationsdokumentationens IoT-klasse og forbindelsesmetode.
  • Find automatiseringer, der bruger cloud-entiteter, eksterne data eller koordinatorer via LAN.
  • Beslut hvilke funktioner der skal virke fysisk, når Home Assistant er stoppet.
  • Test et kontrolleret WAN-udfald uden at afbryde routeren eller lokalnettet.
  • Brug forudsigelige adresser til vigtige enheder og vedligehold tydelig netværksdokumentation.

Fuld redundans er et separat projekt. Selv et enkelt afhængighedskort viser dog, om vigtigt lys, varme eller gardiner afhænger af cloud eller én infrastrukturdels funktion.

KONKLUSION

Lokal Home Assistant gør ikke automatisk hele hjemmet lokalt

Robusthed afhænger af hver enheds kommunikation, integrationstype, routerens og LAN'ets tilgængelighed, Home Assistant-værten samt automatiseringernes design.

Et godt system lover ikke, at alle funktioner overlever alle fejl. Det gør afhængigheder tydelige, bevarer vigtig lokal betjening og definerer sikker adfærd, når cloud eller central er utilgængelig.
