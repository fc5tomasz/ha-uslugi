ZIGBEE COMPARISON

ZHA or Zigbee2MQTT in Home Assistant – which should you choose?

Author: Tomasz Furdal · HA Expert

ZHA and Zigbee2MQTT are two popular ways to manage Zigbee devices in Home Assistant. Both support a local Zigbee network without multiple manufacturer hubs, but differ in architecture, configuration and features.

There is no single best solution for every home. ZHA offers a simple integration directly in Home Assistant, while Zigbee2MQTT provides extensive configuration and broad device support. The right choice is the one that fits the installation.

BASICS

What are ZHA and Zigbee2MQTT?

ZHA

Zigbee Home Automation is built into Home Assistant. With a supported coordinator, you can create a network, pair devices and manage them without a separate Zigbee management system.

Its main advantage is simplicity, and it is fully sufficient for many residential installations.

Zigbee2MQTT

Zigbee2MQTT is a separate project that communicates with Zigbee devices. It exchanges data with Home Assistant through MQTT, requiring an MQTT broker such as Mosquitto.

It offers detailed information, many options and broad device support.

ARCHITECTURE

The main difference

ZHA operates as part of Home Assistant.

Zigbee2MQTT operates separately and communicates through MQTT.

ZHA has a simpler architecture. Zigbee2MQTT offers more independence and configuration options, but a more advanced solution is not always the better choice.

CHOICE

When should you choose each option?

Choose ZHA when:

  • simplicity matters;
  • you want direct management in Home Assistant;
  • you do not need a separate service and MQTT broker;
  • you use common, well-supported devices;
  • your current setup is stable and complete.

Consider Zigbee2MQTT when:

  • the network is large or complex;
  • you use devices from many manufacturers;
  • you need features not exposed by ZHA;
  • you want more device and network detail;
  • MQTT is already part of your setup;
  • you want Zigbee separated from Home Assistant.
COMPATIBILITY

Check the exact device, not only the Zigbee label

A device may work in both systems while exposing different features. Before buying many units, verify the exact model and required functions in the official documentation for the selected solution.

STABILITY

Stability depends on the whole network

Coordinator quality and placement, mains-powered routers, device placement, 2.4 GHz interference, hardware quality and mesh topology all affect stability.

Switching software will not automatically fix a poorly designed Zigbee network. Read the guides to Zigbee stability and choosing a USB, LAN or PoE coordinator.

MIGRATION

Should you migrate from ZHA to Zigbee2MQTT?

If the network is stable and provides the features you need, popularity alone is not a reason to migrate. Consider a change only for a real compatibility limitation, missing feature, greater control or planned expansion.

Moving between ZHA and Zigbee2MQTT may require resetting and pairing devices again, plus changes to entities and automations. This is different from ZHA’s supported coordinator migration within an existing ZHA network.

DECISION

ZHA or Zigbee2MQTT – which should you choose?

For a simple start, ZHA is a sensible choice. For a large mixed network, advanced settings or more control over the Zigbee layer, Zigbee2MQTT may fit better.

Do not rebuild a stable installation only because another solution is more popular.
